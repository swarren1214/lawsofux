[~2 min] Here’s what Miller’s Law means for each of us on Monday morning. Product folks, the useful version of this law is really three words: recognition over recall. Anywhere a user has to remember something exactly, ask whether the screen could just show it instead. [Pause] Engineering, this one’s sneaky. The IDs and codes we generate are part of the UX, whether we think of them that way or not. Confirmation numbers, invite codes, reference IDs: people read them aloud, type them in and write them on sticky notes. So keep them short, chunk them, and avoid look-alike characters like zero and capital O, or one and lowercase l. QA, I love this test because it costs nothing. Read a code over the phone to a teammate and count every mix-up. If two of us can’t pass a code back and forth without errors, our customers definitely can’t. [Ask the room: “Engineering, do any of our generated IDs use characters that are easy to confuse?”] [Let someone answer, and if nobody’s sure, make it a follow-up.] Now, if memory is limited, how do we fit more in? That’s the next law: chunking.
