[~2 min] Similarity on Monday morning. [Point to Product] Product, your question is “Do these do the same thing?” Similarity is how users learn an interface. Once they figure out what one blue button does, they assume every blue button works the same way. Protect that. If they look alike, they should act alike. [Point to Engineering] Engineering, yours is “One style per meaning?” This law lives in the design system. Every button variant, primary, secondary, destructive, should map to exactly one meaning. And that’s something code review can enforce. If a destructive action shows up in the primary style, flag it. [Point to QA] QA, try “predict before you tap.” Before you tap anything, guess what it’s going to do. Every time the result surprises you, a visual promise is being broken, and that’s worth logging. [Ask the room: “QA, would anyone be up for trying predict-before-you-tap on one screen this week?”] [Wait for a hand or two.] Next, we’ll see how a single line can beat both color and spacing: Uniform Connectedness.
